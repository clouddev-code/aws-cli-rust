# aws と awsr の性能比較 (2026-11-07)

## 結論

- **起動と 1 回ごとのコストは awsr が大幅に小さい。** ネットワークを使わない処理では約 10 倍速く (302 ms → 29 ms)、CPU 時間は 1/10 以下、メモリは約 1/4 です。
- **多重実行では差が広がる。** `s3 ls` を 60 回実行すると、並列 16 で経過時間は 5.9 秒 → 1.7 秒、CPU 時間は 34.2 秒 → 1.2 秒になりました。aws は Python の起動処理で CPU を取り合います。
- **S3 の転送は回線が律速で、差は小さい。** 中央値で awsr が 5〜23% 速いものの、試行ごとのばらつき (特に aws の 200 MiB ダウンロード) を考えると、優位と言えるのは小さなファイルの一括転送までです。

## 環境

| 項目 | 内容 |
|---|---|
| マシン | macOS (Darwin 24.6.0, arm64) |
| aws | aws-cli 2.39.5 (Homebrew, Python 3.15.2)。S3 転送は既定の classic クライアント |
| awsr | ブランチ `p4-s3` のリリースビルド (モデル埋め込み) |
| 認証 | 同じ `login_session` プロファイル (両者でキャッシュを共有) |
| 接続先 | `s3://awsr-tool-test` (us-west-2)、計測は日本から |
| 転送設定 | 両者とも既定値 (`max_concurrent_requests` 10、`multipart_threshold` / `multipart_chunksize` 8 MiB) |

## 1. 1 回あたりの所要時間

aws と awsr を交互に 20 回ずつ実行しました (各 1 回のウォームアップ後)。

| コマンド | aws 中央値 | awsr 中央値 | aws p90 | awsr p90 |
|---|---|---|---|---|
| `ec2 describe-instances --generate-cli-skeleton` (ネットワークなし) | 301.7 ms | 29.3 ms | 305.3 ms | 30.1 ms |
| `sts get-caller-identity` | 728.8 ms | 526.3 ms | 754.2 ms | 559.4 ms |
| `s3 ls s3://awsr-tool-test/` | 768.0 ms | 425.9 ms | 800.6 ms | 446.0 ms |

ネットワークを使うコマンドの所要時間は、us-west-2 との往復 (TCP + TLS + リクエスト) が大半を占めます。aws の起動処理だけで約 300 ms かかり、その分が差として残ります。

## 2. 多重実行

`s3 ls s3://awsr-tool-test/` を合計 60 回、並列数を変えて実行しました。CPU 時間は子プロセスの user + sys の合計です。

| 並列数 | aws 経過時間 | awsr 経過時間 | aws CPU 時間 | awsr CPU 時間 | aws 1 回あたり | awsr 1 回あたり |
|---|---|---|---|---|---|---|
| 1 | 44.12 秒 | 25.29 秒 | 20.21 秒 | 1.89 秒 | 735 ms | 422 ms |
| 4 | 12.75 秒 | 6.34 秒 | 25.89 秒 | 1.45 秒 | 213 ms | 106 ms |
| 16 | 5.91 秒 | 1.67 秒 | 34.22 秒 | 1.21 秒 | 99 ms | 28 ms |

1 プロセスの最大メモリ (`/usr/bin/time -l`、`s3 ls` を 3 回) は aws が約 80 MB、awsr が約 18 MB でした。

## 3. S3 の転送

各ケースを 3 回、aws と awsr の実行順を交互に入れ替えて実行しました。

| ケース | aws (3 回) | awsr (3 回) | aws 中央値 | awsr 中央値 | 差 |
|---|---|---|---|---|---|
| アップロード 4 KiB × 200 (`--recursive`) | 4.01 / 3.96 / 3.84 秒 | 3.55 / 3.65 / 3.70 秒 | 3.96 秒 | 3.65 秒 | -8% |
| ダウンロード 4 KiB × 200 (`--recursive`) | 4.30 / 4.63 / 4.28 秒 | 4.09 / 4.12 / 3.88 秒 | 4.30 秒 | 4.09 秒 | -5% |
| アップロード 200 MiB | 15.30 / 17.07 / 18.46 秒 | 12.50 / 18.62 / 14.26 秒 | 17.07 秒 | 14.26 秒 | -16% |
| ダウンロード 200 MiB | 50.50 / 29.56 / 56.62 秒 | 40.52 / 37.24 / 39.03 秒 | 50.50 秒 | 39.03 秒 | -23% |

- 小さなファイルの一括転送では、awsr が 3 回ともわずかに速い結果でした。どちらも 10 並列なので、差の多くは起動とリスト取得の時間です。
- 200 MiB は回線の状態に左右され、ばらつきが大きくなりました。アップロードは範囲が重なっています。ダウンロードは aws が 29.6〜56.6 秒と大きくばらついたのに対し、awsr は 37.2〜40.5 秒で安定していました。ただし 3 回だけなので、差は参考値です。

## 注意点

- 試行回数が少なく (転送は 3 回)、時間帯や回線の混み具合で結果は変わります。
- aws は CRT 転送クライアント (`preferred_transfer_client = crt`) を使わない既定の設定で計測しました。CRT を使うと、大きなファイルの転送は速くなる可能性があります。
- awsr のダウンロードは、パートごとの本文をメモリに読んでからファイルに書き込みます (パートの大きさまで)。aws はストリーミングで書き込みます。
- 1 と 2 の計測スクリプトはこのセッションの作業用ディレクトリで実行しました。3 は `transfer.py` をユーザーのシェルで実行しました。
